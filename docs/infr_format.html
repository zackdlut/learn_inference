INFR 文件格式

扩展名常用 .inference。由 tools/train_mnist_numpy.py 的 save() 写出， 由 C++ ModelFile::load / get_tensor 读取。 所有多字节整数均为小端序（<I / <q / <Q）。

固定文件头 张量元信息（重复 N 次） 锚点字段 数据区（原始 fp32 字节）

1. 文件整体布局

数据区起点，不是文件头。

元信息与 payload 分离：加载时先解析头部即可知道有哪些张量、各占多长；需要时再按 offset 拷贝或 mmap 对应片段。

2. 字段定义

顺序字段类型说明
1magic4 × char固定为 INFR（0x49 0x4E 0x46 0x52）
2versionuint32 LE当前为 1
3num_tensorsuint32 LE张量个数 N，必须 > 0
重复 N 次（每张量一条元信息记录）
4aname_lenuint32 LEUTF-8 名称字节数
4bnamename_len 字节如 fc1.weight
4cdtypeuint32 LE0 = float32
4dndimuint32 LE形状维数（标量时可为 0）
4edimsint64 LE × ndim各维长度，与 NumPy shape 一致
4foffsetuint64 LE在数据区内的起始字节偏移
4gnbytesuint64 LE原始数据长度，须等于 numel × 4
5data_startuint64 LE数据区在整个文件中的起始偏移；写入时 len(header_before_field) + 8
6payload连续字节各张量按保存顺序紧密拼接；单张量内部为 C 连续、小端 fp32

3. 单张量元信息（放大）

fc1.weight → len=10, ndim=2, dims=(128, 784), nbytes=401408 数据区拷贝：memcpy(dst, data + offset, nbytes)

6. 实现注意

  • 不要用 memcpy 直接读入含 padding 的 C 结构体；按字段逐段解析才跨平台稳定。
  • nbytes 必须与 ∏ dims × sizeof(float) 一致，否则 C++ 加载失败。
  • 张量在文件中的顺序与 Python dict 插入顺序一致（3.7+ 保序）。
  • 当前仅支持 version=1 dtype=0；扩展新 dtype 时需同时 bump version。
// 数据区切片（C++）
model_file.data.assign(buf.begin() + data_start, buf.end());
