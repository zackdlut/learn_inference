2. 张量名就是"挂载点"：从名字推出它连到哪个节点

原理

PyTorch 保存权重时，键名就是模块树上的路径（state_dict）。GPT2LMHeadModel.transformer.h[3].attn.c_attn.weight 去掉前缀就是 h.3.attn.c_attn.weight。所以名字本身已经编码了"这个张量属于哪一层、哪个子模块、是哪个参数"。构图代码要做的，就是对每一层按固定模板生成节点，再按名字把权重接到正确的输入槽上。可以写成一个映射：

\[ \text{name} = \texttt{h.}\,\ell\,\texttt{.}\,\text{module}\,\texttt{.}\,\text{param} \;\;\longmapsto\;\; (\text{node} = \texttt{h.}\ell\texttt{.module},\ \ \text{slot} = \mathrm{slot}(\text{param})) \]

其中 \(\mathrm{slot}(\texttt{weight}) = 1,\ \mathrm{slot}(\texttt{bias}) = 2\)，输入 0 留给上游激活。权重数 \(= 160 - 12 = 148\)：每块 12 个参数 × 12 块，加 wte、wpe、ln_f.weight、ln_f.bias。

3. 整体计算图（宏观）

原理

计算图是一个有向无环图（DAG）\(G = (\mathcal{V}, \mathcal{E})\)：节点是算子，边是张量。每个节点的输出只依赖它的输入：

\[ v_{\text{out}} = \mathrm{op}_n\big(v_{\text{in},1}, \dots, v_{\text{in},k};\ \text{attrs}_n\big) \]

整个模型就是这些函数的复合。GPT-2 的主干是一条长链：嵌入 → 12 个块 → ln_f → lm_head，块内部有残差分叉。图里共有：

\[ |\text{nodes}| = \underbrace{3}_{\text{embed}} + \underbrace{12\times 10}_{\text{blocks}} + \underbrace{2}_{\text{ln\_f, lm\_head}} = 125,\qquad |\text{weights}| = 148,\qquad |\text{inputs}| = 2 \]

权重共享在图里表现为同一个 Value 有两条出边：嵌入查表读 wte 的行，lm_head 用它做矩阵乘。共享的是同一块内存，而不是两份拷贝。

4. 单个 Transformer 块的子图（h.ℓ.*）

原理与公式

这张子图就是下面两行公式的逐节点展开，每个算子对应公式中的一个函数（下标是图中的节点编号）：

\[ \begin{aligned} u &= x + \underbrace{\mathrm{Linear}_{4}\Big(\mathrm{Attn}_{3}\big(\mathrm{Linear}_{2}(\mathrm{LN}_{1}(x))\big)\Big)}_{\text{attention branch}} \qquad (\text{add}_5) \\ x' &= u + \underbrace{\mathrm{Linear}_{9}\Big(\mathrm{GELU}_{8}\big(\mathrm{Linear}_{7}(\mathrm{LN}_{6}(u))\big)\Big)}_{\text{MLP branch}} \qquad (\text{add}_{10}) \end{aligned} \]

为什么要转置权重：GPT-2 的 Conv1D 算 \(y = xW + b\)，\(W\) 形状 \((d_{in}, d_{out})\)；本项目的 linear 和 nn.Linear 一样算 \(y = xW'^{\top} + b\)，\(W'\) 形状 \((d_{out}, d_{in})\)。令 \(W' = W^{\top}\) 即可：

\[ x\,(W^{\top})^{\top} + b = xW + b \]

转置只在加载时做一次（transpose(0,1).contiguous()），推理时没有额外开销。linear 的形状推断检查 \(x\) 的第 1 维等于 \(W'\) 的第 1 维，所以忘了转置 c_attn、c_fc、mlp.c_proj 时，finalize() 会直接报错。但 attn.c_proj 是 \(768\times768\) 的方阵，转不转置形状都对得上，不会报错，只会悄悄算出错误结果。所以转置要按"所有 Conv1D 权重"统一处理，不能靠形状检查兜底，最终还要和参考实现逐层对拍。

残差边让 \(x\) 和 \(u\) 各有两个消费者，这会直接影响第 7 节的内存释放时机。

5. 把 causal_attention 展开成细粒度子图

原理与公式

融合节点和展开子图计算的是同一个函数（\(h = 1,\dots,12\) 为头编号）：

\[ \mathrm{CausalAttn}(\mathrm{qkv}) = \mathrm{merge}_h\Big(\mathrm{softmax}\big(\tfrac{1}{\sqrt{d_h}}\,Q_h K_h^{\top} + M\big)\, V_h\Big),\qquad M_{t,s} = \begin{cases} 0 & s \le t \\ -\infty & s \gt t \end{cases} \]

选哪种粒度是工程上的取舍：

  • 细粒度：每个节点简单、容易单独测试；但会把 \((12, T, T)\) 的分数矩阵作为中间 Value 存下来。\(T = 1024\) 时每个这样的张量就是 \(12\times1024^2\times4\,\text{B} = 48\,\text{MiB}\)，而上图第一个 bmm、mul_scalar、causal_mask、softmax 四步各产生一个。
  • 融合节点：分数矩阵只是算子内部的临时变量，逐行算完 softmax 就可以丢掉。FlashAttention 更进一步，分块计算，完全不把 \(T\times T\) 矩阵写进显存。

另外，slice、split_heads、transpose 在本项目里都可以用 Tensor 的 view（reshape/transpose）零拷贝实现，真正需要计算的只有两次 bmm、缩放、掩码和 softmax。

原理
      
构图代码只做"登记"，不做计算：add_node 只记录"谁是输入、用哪个算子"，返回输出 Value 的 id。真正的计算要等 Executor::run。这种先描述、后执行的方式叫静态图（define-and-run），好处是执行前就能看到整张图，可以做形状检查、内存规划和算子融合；PyTorch 默认的 eager 模式则是边执行边构图（define-by-run）。

      
注意 add_block 被调用 12 次，用的是同一个模板，只是名字前缀和权重不同。这正对应 config 里 n_layer = 12：config 换成 gpt2-medium（\(L = 24,\ d = 1024,\ H = 16\)），同一份构图代码就能生成 24 块的图。

    

  


  
  
7. finalize()：拓扑排序 + 形状推断 + 使用计数

  

    
以一个块为例，finalize() 不跑任何计算，就能填出下表（T 是构图时给定的数）：

    

      
执行序节点type输入形状输出形状输出的消费者数

      
1h.ℓ.ln_1layer_norm(T,768), (768), (768)(T,768)1

      
2h.ℓ.attn.c_attnlinear(T,768), (2304,768), (2304)(T,2304)1

      
3h.ℓ.attncausal_attention(T,2304)(T,768)1

      
4h.ℓ.attn.c_projlinear(T,768), (768,768), (768)(T,768)1

      
5h.ℓ.residual_1add(T,768), (T,768)(T,768) = u2

      
6h.ℓ.ln_2layer_norm(T,768), (768), (768)(T,768)1

      
7h.ℓ.mlp.c_fclinear(T,768), (3072,768), (3072)(T,3072)1

      
8h.ℓ.mlp.actgelu(T,3072)(T,3072)1

      
9h.ℓ.mlp.c_projlinear(T,3072), (768,3072), (768)(T,768)1

      
10h.ℓ.residual_2add(T,768), (T,768)(T,768) = x⁽ℓ⁾2（下一块的 ln_1 和 residual_1）

    

    
原理与公式
      
拓扑排序：给节点排一个顺序，使每条边 \(u \to v\) 都满足 \(u\) 排在 \(v\) 前面。常用 Kahn 算法：反复取出入度为 0 的节点，删掉它的出边。DAG 一定存在这样的顺序，若图中有环则排不出来。GPT-2 的图基本是一条链，拓扑序就是构图顺序。

      
形状推断：按拓扑序对每个节点调用 Op::inference_shape，例如 linear 的规则是

      \[ x: (M, K),\ \ W: (N, K),\ \ b: (N) \;\Longrightarrow\; y: (M, N) \]
      
形状沿边一路传播，权重形状不匹配（比如忘了转置 Conv1D 权重）会在这一步报错，而不是等到运行时。

      
使用计数：\(\mathrm{uses}(v) = |\{\,n : v \in \mathrm{inputs}(n)\,\}|\)，即有几个节点读这个 Value。Executor 每执行完一个节点就把它各输入的计数减 1，减到 0 的中间结果就可以释放。

    

  


  
  
8. Executor：中间结果的生命周期与内存峰值

  

    

      
    

    
原理与公式
      
对每个中间 Value \(v\)，记它在第 \(p(v)\) 步被产生，最后一个消费者在第 \(c(v)\) 步执行，则它的存活区间是 \([p(v),\ c(v)]\)。执行第 \(s\) 步时同时占用的内存为：

      \[ \mathrm{Mem}(s) = \sum_{v:\ p(v)\,\le\, s\,\le\, c(v)} \mathrm{bytes}(v),\qquad \mathrm{Peak} = \max_s \mathrm{Mem}(s) \]
      
一个块内峰值出现在 ⑧ gelu：输入 c_fc 输出（4 份）、输出 gelu（4 份）、加上残差要用的 \(u\)（1 份），共 \(9 \times T \times 768 \times 4\) 字节。\(T = 1024\) 时约 27 MiB；如果不释放、把 12 块所有中间结果都留着，则是每块 18 份 × 12 块 ≈ 648 MiB。这就是 Executor::set_reuse(true) 的意义，hello_graph 打印的 peak_bytes 就是这个 \(\mathrm{Peak}\)。

      
还有两个比块内激活更大的东西：

      
    
        
  • 注意力分数：融合节点内部的临时 \((12, T, T)\)，\(T=1024\) 时 48 MiB。
    • 
        
  • logits：\((T, 50257)\)，\(T=1024\) 时约 196 MiB，比整个块的峰值还大得多。推理时只需要最后一行，所以常见的图优化是在 lm_head 之前插入一个"取最后一行"的节点，把 lm_head 的输入从 \((T,768)\) 变成 \((1,768)\)：logits 缩小到 196 KB，lm_head 的计算量也降为原来的 \(1/T\)。
    •
